# Proof-Bearing Reference Cycle

## Why this is more than a static demo

- The GoalOS runtime actually generated formation, fresh-proof and transfer episodes.
- The exact candidate release and verifier bundle are hashed.
- Proof-time learning is zero.
- Protected case sets are committed before adjudication.
- A separately generated Ed25519 verifier identity signs the Fresh Proof record.
- A different identity signs accountable admission.
- A third identity signs the Authority Envelope.
- The authority service verifies the envelope and denies prohibited actions.
- A material change invalidates proof and contracts authority.
- Rollback is executed.
- A new exact release undergoes new proof, admission and authority issuance.
- Chronicle links all transitions.

## Why this is still a reference cycle

The mission environment is synthetic and deterministic. The cycle demonstrates mechanism integrity, not customer-production performance or physical-grid authority.
